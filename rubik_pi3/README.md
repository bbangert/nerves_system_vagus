# Thundercomm Rubik Pi 3 (QCS6490): Vagus product layer

This target is [nerves_system_rubik_pi3](https://github.com/bbangert/nerves_system_rubik_pi3),
the board support for the Thundercomm Rubik Pi 3, plus the layer that Vagus
needs on top of it. The board system is vendored under `base/` and holds
everything about the board itself: boot chain and A/B updates, UFS
flashing and storage layout, kernel and patches, firmware, the AI
foundation, WiFi/BT and the hardware validation record. Start with
[base/README.md](base/README.md) and `base/docs/`.

## What this layer adds

| Feature | Description |
| --- | --- |
| Containers | podman 6.1.4 + netavark (nftables) + cgroup v2 — the same stack as `dragon_q6a` |
| Bluetooth userspace | D-Bus, BlueZ (`bluetoothctl`, `btmon`, `btmgmt`, `hciconfig`/`hcitool`), bluez-alsa (A2DP source, SBC); kernel side in `linux-bluetooth.config` |
| Memory tuning | `linux-memory.config` (swap/reclaim, `PANIC_TIMEOUT=10`) and `/etc/sysctl.conf` |
| nfs-utils | `rpc.nfsd`/`rpc.mountd`/`exportfs` for the knfsd in `base/linux-hwdebug.config`; nothing starts them |

`linux-*.config`, `rootfs_overlay/etc/sysctl.conf` and `package/vagus-*`
are synced from the repo's `shared/` by `make sync`.

## How the layers fit

`base/` is a `git subtree --squash` of a tagged nerves_system_rubik_pi3 release
(`base/VERSION`). Never edit it here; fix the base repo, tag it, then:

```sh
make base-pull BASE=rubik_pi3 REF=v0.1.1   # subtree pull + make sync
```

Three files are generated by `scripts/sync-base.sh` from `base/` plus this
directory's fragments, and carry a DO NOT EDIT header:

| Generated | From |
| --- | --- |
| `nerves_defconfig` | `base/nerves_defconfig` + `nerves_defconfig.fragment` |
| `Config.in` | `base/Config.in` + `Config.in.fragment` |
| `rootfs_overlay/etc/erlinit.config` | `base/rootfs_overlay/etc/erlinit.config` + `erlinit.config.fragment` |

In the defconfig merge, a fragment symbol replaces base's, except list
options (overlays, kernel fragments, patch dirs and the like), where the
fragment value is appended. Base paths are rewritten to `base/`, since
`NERVES_DEFCONFIG_DIR` is this directory. Buildroot applies
`base/rootfs_overlay` and then `rootfs_overlay`, so a product file wins.
`external.mk` includes `base/external.mk` for the board packages.

```sh
make sync     # regenerate after editing a fragment or shared/
make check    # CI: fails on drift, or if mix.exs pins a different
              # nerves_system_br or toolchain than base/mix.exs
```

`base/` carries its own licensing in `base/REUSE.toml`.

## Container runtime (podman)

The same stack as `dragon_q6a`, so HA Core and apps run as containers that
Vagus drives one operation at a time through the `podman` CLI; there is no
engine daemon. Three pieces:

| Piece | Where |
| --- | --- |
| Engine | `package/vagus-podman` (podman 6.1.4, with the baked `/etc/containers/containers.conf` and `storage.conf`), `package/vagus-netavark` (netavark 2.1.0, nftables driver, no aardvark-dns), `package/vagus-crun` (crun 1.30.1), all synced from `shared/package/` by `make sync`; Buildroot's `conmon`, `catatonit`, `containers-image-config`, `nftables` and util-linux |
| Kernel support | `linux-containers.config` — a **shared** fragment (`shared/`, `make sync`, `make check`); overlayfs, cgroup controllers, nftables + NAT, bridge/veth, seccomp, `CGROUP_BPF` |
| Runtime mounts | `erlinit.config.fragment` mounts `cgroup2` on `/sys/fs/cgroup` and `configfs`; both GRUB slots in `base/grub.cfg` pass `cgroup_no_v1=all cgroup_enable=memory` |

`<graphroot>/tmp` must exist before the first pull (Vagus creates it), and
pulls need a synced clock: the board has no RTC backup battery (see
base/README.md). Host-network containers get a copy of `/etc/hosts`, which
is why base ships one with a `::1` line, and podman (a cgo binary) resolves
users and hosts through glibc's NSS (`/etc/nsswitch.conf`, also from base).

## Validation (product layer)

Board rows are in `base/docs/validation.md`.

| Gate | Status |
