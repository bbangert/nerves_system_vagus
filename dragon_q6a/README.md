# Radxa Dragon Q6A (QCS6490): Vagus product layer

This target is [nerves_system_dragon_q6a](https://github.com/bbangert/nerves_system_dragon_q6a),
the board support for the Radxa Dragon Q6A, plus the layer that Vagus needs
on top of it. The board system is vendored under `base/` and holds
everything about the board itself: boot chain and A/B updates, flashing,
kernel and patches, firmware, the AI foundation, WiFi/BT, audio and the
hardware validation record. Start with [base/README.md](base/README.md)
and `base/docs/`.

## What this layer adds

| Feature | Description |
| --- | --- |
| Containers | podman 6.1.4 + netavark (nftables) + cgroup v2 — not yet device-proven on this image |
| Bluetooth userspace | D-Bus, BlueZ (`bluetoothctl`, `btmon`, `btmgmt`, `hciconfig`/`hcitool`), bluez-alsa (A2DP source, SBC); kernel side in `linux-bluetooth.config`; `/etc/bluetooth/main.conf` sets the advertising interval the AIC8800 needs |
| Memory tuning | `linux-memory.config` (swap/reclaim, `PANIC_TIMEOUT=10`) and `/etc/sysctl.conf` |
| nfs-utils | `rpc.nfsd`/`rpc.mountd`/`exportfs` for the knfsd in `base/linux-hwdebug.config`; nothing starts them |

`linux-*.config`, `rootfs_overlay/etc/sysctl.conf` and `package/vagus-*`
are synced from the repo's `shared/` by `make sync`.

## How the layers fit

`base/` is a `git subtree --squash` of a tagged nerves_system_dragon_q6a release
(`base/VERSION`). Never edit it here; fix the base repo, tag it, then:

```sh
make base-pull BASE=dragon_q6a REF=v0.1.1   # subtree pull + make sync
```

Three files are generated by `scripts/sync-base.sh` from `base/` plus this
directory's fragments, and carry a DO NOT EDIT header:

| Generated | From |
| --- | --- |
| `nerves_defconfig` | `base/nerves_defconfig` + `nerves_defconfig.fragment` |
| `Config.in` | `base/Config.in` + `Config.in.fragment` |
| `rootfs_overlay/etc/erlinit.config` | `base/rootfs_overlay/etc/erlinit.config` + `erlinit.config.fragment` |

In the defconfig merge, a fragment symbol replaces base's, except list
options (overlays, kernel fragments, patch dirs and the like), where the
fragment value is appended. Base paths are rewritten to `base/`, since
`NERVES_DEFCONFIG_DIR` is this directory. Buildroot applies
`base/rootfs_overlay` and then `rootfs_overlay`, so a product file wins.
`external.mk` includes `base/external.mk` for the board packages.

```sh
make sync     # regenerate after editing a fragment or shared/
make check    # CI: fails on drift, or if mix.exs pins a different
              # nerves_system_br or toolchain than base/mix.exs
```

`base/` carries its own licensing in `base/REUSE.toml`.

## Container runtime (podman)

HA Core and apps run as podman containers, which Vagus drives one operation
at a time through the `podman` CLI; there is no engine daemon. Three pieces
have to be present:

| Piece | Where |
| --- | --- |
| Engine | `package/vagus-podman` (podman 6.1.4, with the baked `/etc/containers/containers.conf` and `storage.conf`), `package/vagus-netavark` (netavark 2.1.0, nftables driver, no aardvark-dns), `package/vagus-crun` (crun 1.30.1); Buildroot's `conmon`, `catatonit`, `containers-image-config`, `nftables` and util-linux |
| Kernel support | `linux-containers.config` — a **shared** fragment (`shared/`, `make sync`, `make check`); overlayfs, cgroup controllers, nftables + NAT, bridge/veth, seccomp, `CGROUP_BPF` |
| Runtime mounts | `erlinit.config.fragment` mounts `cgroup2` on `/sys/fs/cgroup` and `configfs`; **both** GRUB slots in `base/grub.cfg` pass `cgroup_no_v1=all cgroup_enable=memory` |

Notes for anyone touching this:

- The three `vagus-*` recipes are synced from `shared/package/` by
  `make sync`; edit them there. `make check` fails on drift.
- The baked config is profile-neutral with the frugal (small-RAM) values.
  Vagus writes `/run/vagus/podman/containers.conf` at boot and points
  `CONTAINERS_CONF_OVERRIDE` at it to pick the board's profile.
- Images live under `/root/containers/storage`; container state is in the
  transient store on `/run`, so every container is recreated each boot.
- `/etc/resolv.conf` is a symlink to `/run/resolv.conf`, not the skeleton's
  `../tmp/resolv.conf`; Vagus writes `/run/resolv.conf` at boot.
- The app-data partition mounts at `/data`, which the Nerves skeleton ships
  as a symlink to `/root` — so `mount`/`/proc/mounts` show the partition on
  **`/root`**, and container data really does live on writable storage.
- Host-network containers get a copy of `/etc/hosts`, which is why base
  ships one with a `::1` line, and podman (a cgo binary) resolves users and
  hosts through glibc's NSS (`/etc/nsswitch.conf`, also from base).

> **An OTA cannot update `grub.cfg` on this board.** `fwup.conf` writes it to
> the ESP only in `task complete` (a full flash). A device that OTAs into a
> new version keeps its previous kernel cmdline, so any *future* cmdline
> change (including the cgroup flags above) needs a full reflash.

## Validation (product layer)

Board rows are in `base/docs/validation.md`.

| Component | Version | Notes |
|---|---|---|
| podman | 6.1.4, with netavark 2.1.0, crun 1.30.1, conmon 2.1.8, catatonit 0.2.1 | ran Core and the bench apps, driven by hand, in a throwaway build, 2026-10-13; not yet device-proven as shipped |
| Container stack (Vagus) | — | the full Vagus stack was device-proven on balenaEngine through v0.4.0 (Core, apps, MQTT, ingress, OTA, unclean power cycle); on the podman image it is pending |
| QNN from an app container | — | inference on the Hexagon DSP from an app container, 2026-10-12, kernel 7.2.10 |
| BlueZ / BLE | BlueZ 5.79 | BLE scan/advertise/GATT on the onboard AIC8800, 2026-07-25/26; a TP-Link UB500 USB dongle discoverable via bluetoothd/D-Bus. BlueZ cancels discovery when the requesting D-Bus client disconnects, so inbound scanning needs a persistent client |
