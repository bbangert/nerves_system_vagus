# Radxa ROCK 4D (RK3576): Vagus product layer

This target is [nerves_system_rock_4d](https://github.com/bbangert/nerves_system_rock_4d),
the board support for the Radxa ROCK 4D, plus the layer that Vagus needs on
top of it. The board system is vendored under `base/` and holds everything
about the board itself: UFS boot with U-Boot in SPI NOR, A/B updates,
flashing (`base/scripts/flash-ufs.sh`), the vendor kernel and its patches,
GPU/NPU userspace, WiFi/BT and the hardware validation record. Start with
[base/README.md](base/README.md).

## What this layer adds

| Feature | Description |
| --- | --- |
| Containers | podman 6.1.4 + netavark (nftables) + cgroup v2 |
| Bluetooth userspace | D-Bus, BlueZ (`bluetoothctl`, `btmon`, `btmgmt`, `hciconfig`/`hcitool`), bluez-alsa (A2DP source, SBC); kernel side in `linux-bluetooth.config`; `/etc/bluetooth/main.conf` sets the advertising interval the AIC8800 needs; Realtek USB BT firmware (`rtl_bt`) for dongles such as the TP-Link UB500 |
| Memory tuning | `linux-memory.config` (swap/reclaim, `PANIC_TIMEOUT=10`) and `/etc/sysctl.conf` |

`linux-*.config`, `rootfs_overlay/etc/sysctl.conf` and `package/vagus-*`
are synced from the repo's `shared/` by `make sync`.

## How the layers fit

`base/` is a `git subtree --squash` of a tagged nerves_system_rock_4d release
(`base/VERSION`). Never edit it here; fix the base repo, tag it, then:

```sh
make base-pull BASE=rock_4d REF=v0.2.1   # subtree pull + make sync
```

Three files are generated by `scripts/sync-base.sh` from `base/` plus this
directory's fragments, and carry a DO NOT EDIT header:

| Generated | From |
| --- | --- |
| `nerves_defconfig` | `base/nerves_defconfig` + `nerves_defconfig.fragment` |
| `Config.in` | `base/Config.in` + `Config.in.fragment` |
| `rootfs_overlay/etc/erlinit.config` | `base/rootfs_overlay/etc/erlinit.config` + `erlinit.config.fragment` |

The merge rules are the same as for the other base targets; see
`dragon_q6a/README.md`. `base/` carries its own licensing in
`base/REUSE.toml`.

## Container runtime (podman)

The engine, kernel support and runtime mounts are the same as dragon_q6a's
(see `dragon_q6a/README.md`, "Container runtime"), with one difference: the
kernel cmdline needs no cgroup flags. base mounts no cgroup v1 hierarchy,
so `erlinit.config.fragment`'s `cgroup2` mount gets every controller, and
the vendor kernel enables the memory controller by default.

Images live under `/root/containers/storage` on the f2fs data partition
(`/dev/rootdisk0p5`).
